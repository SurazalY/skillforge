# 统一分发 Prompt

下面内容应原样发送给每个参测 Agent。除 `<仓库绝对路径>` 外，不要为不同 Agent 修改措辞。

---

你正在参加一次代码分析能力评测。你的任务是在一个连续会话中，对给定 SkillForge 仓库完成一套只读分析题，并最终提交一份完整 Markdown 答卷。

仓库绝对路径：`<仓库绝对路径>`

请严格遵守以下规则：

1. 先进入仓库根目录，完整阅读 `agent-eval/questions.md`、`agent-eval/answer-template.md`、`agent-eval/scoring-rubric.md` 和 `agent-eval/snapshot-manifest.md`，然后完成 `questions.md` 中的 Q1–Q7。
2. 必须在一次连续任务中完成全部题目，不要只挑选部分问题，不要中途要求我替你做技术判断。
3. 这是只读评测：不得修改、创建、删除或格式化仓库中的任何产品代码、测试、文档、配置及 Git 状态。允许 pytest 自己产生缓存；允许在 `/tmp` 中运行一次性复现脚本。
4. 不得联网，不得读取仓库根目录之外的文件或目录；`/tmp` 仅可用于你本次创建的临时复现内容，不得搜索其中已有文件。
5. 不得寻找标准答案、评分人的私有文件、其他 Agent 的答案或历史评审记录。即使你猜测它们存在，也不得尝试定位或读取。
6. 所有关键结论必须引用当前仓库中的实现，格式为 `相对路径:行号`。跨模块结论应引用调用链的两端。不要用 README 或测试名称代替实现证据。
7. 所有实际运行的命令都要在答卷末尾记录命令、退出码和关键输出。没有运行或无法确认的内容必须明确标记为“未验证”，不得编造结果。
8. 清楚区分以下三类内容：
   - 已由代码或命令确认的事实；
   - 根据证据作出的推断；
   - 你提出的修改建议。
9. 不要实际修复题目中的 Bug。只做复现、根因分析、影响分析以及修复和回归测试设计。
10. 最终只返回一份完整 Markdown 答卷，章节结构必须遵循 `agent-eval/answer-template.md`。不要把答案写入仓库文件。

质量要求：优先保证正确和可复核。答案长短不单独计分，但编造符号、文件、行号、测试结果或运行行为会被重罚。遇到主实现、历史副本、文档和测试互相不一致时，应指出权威依据和不一致，而不是自行补全。

时间上限为 120 分钟。现在开始，直到 Q1–Q7 和最终自检全部完成后再提交最终答案。
