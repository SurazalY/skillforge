# 公开评分规则

总分 100 分：Q1 15、Q2 20、Q3 15、Q4 12、Q5 12、Q6 16、Q7 10。

评分优先级如下：

1. **正确性与可复现性**：运行事实准确，根因能解释全部症状，建议不会破坏既有行为。
2. **证据质量**：关键结论有精确 `path:line`，调用链有两端证据，命令和退出码真实。
3. **长程一致性**：不同章节对 phase、状态、预算、证据类型的说法不冲突。
4. **边界意识**：区分主实现、嵌套旧副本、文档、测试和环境因素；区分事实、推断和建议。
5. **表达效率**：信息密度高，能给出紧凑时序和明确因果，不用大段源码填充答案。

## 通用扣分

- 编造不存在的文件、符号、调用或命令结果：每处至少扣 3 分；若影响核心结论可扣完对应题。
- 关键结论无代码证据：该点最多得一半分。
- 只引用测试名或 README、未核对实现：该点最多得一半分。
- 把环境问题直接归因于产品代码，或把已有防护误报为漏洞：按影响扣 2–6 分。
- 修改了产品代码/测试、联网、读取仓库外路径、借用另一位 Agent 输出：该次结果应标记为不合规。
- 明知未验证却写成已验证：按幻觉处理；坦诚写“未验证”不额外扣幻觉分。

## 平局处理

总分相差不超过 3 分时，依次比较：

1. 幻觉/伪证据更少者；
2. Q2+Q3（长程架构与上下文）合计更高者；
3. Q4+Q5（Bug 根因与回归设计）合计更高者；
4. 在更短答案中达到同等证据覆盖者。
