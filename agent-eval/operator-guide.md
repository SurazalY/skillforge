# 双 Agent 对比评测操作手册

## 1. 冻结评测快照

从开始 Agent A 作答到 Agent B 提交之前，不要修改仓库内容。确认两个 Agent 都能访问同一个只读快照，并核对 `agent-eval/snapshot-manifest.md`。

本仓库原本就有大量未提交改动，因此不要用 `git clean`、`git reset` 或重新 checkout 来“清理”它；这些操作可能破坏本次评测所针对的实际快照。

如果两个 Agent 必须使用独立副本，应从当前目录做两份完整复制，并确保两份中的 manifest 和代码哈希相同。复制时不要把任何 Agent 的答卷放进副本。

## 2. 统一评测条件

在开始前固定并记录：

- Agent 产品与版本；
- 模型名称和版本；
- reasoning / thinking 档位；
- 工具权限；
- 上下文长度或 token 限制；
- 120 分钟时间上限；
- 是否允许子 Agent。若允许，两个参测者必须相同；
- 仓库绝对路径和快照指纹。

除“要比较的 Agent 本身”以外，尽量不要同时改变模型、推理强度、工具权限或时限，否则无法判断差异来自哪里。

## 3. 分发给 Agent A

1. 新建一个空白会话，不提供本次设计测试时的聊天记录。
2. 设置工作目录为评测仓库根目录。
3. 打开 `agent-eval/distribution-prompt.md`，将 `<仓库绝对路径>` 替换为实际路径。
4. 原样发送完整 Prompt，不追加提示或暗示答案。
5. Agent 工作期间只回答必要的环境问题，不提供技术线索。
6. 保存它的最终原始 Markdown 为仓库外的 `agent-a-answer.md`。不要人工润色、补行号或修正命令结果。
7. 记录开始时间、结束时间、是否超时、是否违反只读/联网/路径约束。

## 4. 分发给 Agent B

对 Agent B 重复完全相同的流程：新会话、相同快照、相同 Prompt、相同权限和时限。

不要告诉 Agent B：

- Agent A 的答案、进度或工具选择；
- 哪些题 Agent A 做错了；
- 评分人已经确认的运行结果；
- 标准答案保存在哪里。

将最终原始答案保存为仓库外的 `agent-b-answer.md`。

## 5. 回收答案前检查

只做形式检查，不做内容修正：

- 是否包含 Q1–Q7；
- 是否包含最终自检；
- 是否是 Agent 原始输出；
- 是否记录超时、崩溃或人为介入；
- 是否有修改仓库、联网或越界读取的迹象。

缺章节也不要让其中一个 Agent 单独补考；除非两个 Agent 都按同样规则获得一次补交机会。

## 6. 交给评分人

把以下内容发回当前评分会话：

```text
请按照之前固化的隐藏标准答案进行盲评。以下是两个 Agent 的原始答案。

评测条件：
- Agent A：<产品/模型/推理档位/工具权限/耗时>
- Agent B：<产品/模型/推理档位/工具权限/耗时>
- 快照：agent-eval/snapshot-manifest.md
- 规则偏离：<无，或逐项说明>

--- Agent A 原始答案 ---
<粘贴完整答案或附上 agent-a-answer.md>

--- Agent B 原始答案 ---
<粘贴完整答案或附上 agent-b-answer.md>
```

如果答案很长，可以把两个 Markdown 文件放在一个不提供给参测 Agent 的单独目录，再将文件路径告诉评分人。

## 7. 最终评审会得到什么

评分报告应包含：

- Q1–Q7 分项分和总分；
- 幻觉、伪造运行结果和错误引用清单；
- 关键代码引用抽查；
- 长程前后一致性；
- 两个 Bug 的根因与回归设计质量；
- 安全边界是否误判；
- 最终推荐、适用场景和置信度。

总分接近时，优先选择幻觉更少、Q2+Q3 更强的 Agent，而不是答案更长的 Agent。
