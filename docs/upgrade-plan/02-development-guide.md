版本：2026-09-12。与[增订方案](01-addendum.md)配套；原方案中未被增订覆盖的设计继续有效。本文件定义开发合同，不替阶段主控执行代码研究或测试。

2026-09-13 现状校正以 [A 报告](reports/A-stage-report.md)为依据：已有 OpenAI 格式入口可用，XML 当前是唯一工具协议；原生工具和缺缓存字段显示 unknown 都是 B 目标。当前 SkillForge 无 FastAPI，对外服务不新增，也不安排拆除。实际源码位于 `skillforge/`。A-06 已保存可恢复 Git 基线 `f351988c1dda3bb62012580d4b3fa08fde9b8b8a` 并报告导出核对，用户已关闭 A、批准并关闭 B。B 使用该源码基线及工作区最新交接文档；恢复在线配置需本地另备 `.env`。C 须另行启动。

## 1. 首版用户路径与依赖

用户从仓库终端启动 SkillForge，输入任务。运行时形成任务范围与验收要求，模型通过原生工具协议提出动作；网关检查授权与文件版本，执行后保存结果和工件。长输出按需回查，上下文在完整消息组边界压缩。用户可在 CLI 中控制任务，重启后依据真实状态恢复。任务完成后提炼候选 Skill，审核后的版本在之后的适用任务中按需加载。

```text
pico 式 one-shot / REPL / resume
    -> TaskContract 与工作流
    -> ContextView -> OpenAI 格式模型适配
    -> ToolCallGroup -> 工具网关 -> 本地执行器
    -> ToolResult / Artifact / VerificationRecord
    -> CompletionGate -> 交付
    -> 后置候选学习（当前 CLI 生命周期，独立预算）

SQLite + 工件目录：保存运行事实、调用、事件、版本与恢复定位
只读子任务：在需要独立调查时插入，不能成为第二个工作区写入者
```

实现依赖：A 固定基线；B 先做最小存储，再做协议、工具与上下文；C 完善长进程、交互与恢复；D 完善记忆、Skill 与只读委派；E 做综合对照和终端诊断。每阶段必须完成自身必要验证，不把基本正确性拖到 E。

## 2. 按模块确定最小交付

| 模块与原章节 | 用户得到的功能 | 本轮技术边界 | 主责阶段 |
|---|---|---|---|
| 运行时/模型 01 | 可用模型接入保持，工具动作结构化 | ProviderAdapter、不可变 ModelResponse、合法消息组；保留工作流骨架 | B |
| 提示词/缓存 02 | 费用和缓存失效可解释 | P0/P1 稳定、动态尾部、能力档案和实际 usage；不硬写供应商参数 | B，E 展示 |
| 压缩/工件 03 | 长任务可继续、原文可回查 | 首次输出整形、Token 准入、完整调用组、可提交摘要 checkpoint | B |
| 网关/写入 04 | 普通任务自主推进且不越界 | 严格参数、调用身份、范围授权/精确审批、补丁哈希前态、差异记录 | B，C 补恢复 |
| 进程 05 | 长命令能看进度、取消和辨别未知状态 | 本地受管 ProcessJob、并发排空、终态确认；无服务依赖 | C |
| 仓库/记忆 06 | 复用线索而不误信旧事实 | 文件哈希、来源/范围、依赖失效、有限关键词/FTS5 检索 | B 建稳定快照，D 深化 |
| Skill 07 | 从任务生成可审核经验 | 结构化证据候选、仓库范围、版本、按需读取、撤回、独立预算 | D |
| 子 Agent 08 | 独立调查可有界并行 | 两个只读子任务、隔离消息/用量、父级预算、结果新鲜度 | D |
| 验证/完成门 09 | “完成”有适用证据 | TaskContract、按检查类型记录、当前版本、真实人工确认 | B；各阶段接入 |
| 本地存储 10 | 状态与事件一致、重复动作可识别 | SQLite 短事务、工件就绪协议、单一事实源；不做 HTTP/SSE | B 基础，C 生命周期 |
| 交互 11 | 过程可控、差异和失败可查看 | CLI 安全边界的 steer/pause/cancel/resume、时间线、差异 | C，E 完善 |
| 恢复 12 | 重启后知道可续用、需重验或未知 | 调用/进程核对、文件前后态、工作区所有权、权限与版本重验 | C |
| 可观测/评测 13 | 知道为何贵、慢或未通过 | 正式记录驱动的 CLI Context Inspector、分层对照 | 数据字段 B/C/D，汇总 E |

每行是一组职责，不要求一个新 package、Repository 类或插件接口。优先沿用当前文件约定，只有为打通上述合同才拆分代码。

## 3. 需要跨阶段保持的合同

下表是语义要求，不是必须照抄的数据库 schema。阶段主控通过子报告记录实际合同路径与版本；后续不得另建一套同义身份。

| 合同 | 最小含义 | 首次负责 | 后续使用者 |
|---|---|---|---|
| TaskContract | 用户目标、范围、禁止项、验收种类、revision；摘要不能改授权 | B | C 控制、D 委派/学习、E 评测 |
| ModelResponse | text/tool_calls/finish_reason/usage 与必要 provider 状态，单响应独立归属 | B | C 取消、D 并行、E 成本 |
| ToolCallGroup | 唯一调用身份与完整结果关联；未闭合组不压缩 | B | C 恢复、D 子结果 |
| Run/Event/ToolCall | 状态与事件同事务，已接受意图可定位，完成动作不因重连重执行 | B | C/D/E |
| Artifact/ToolResult | 原文工件、摘要、哈希、范围、解析状态；READY 才作完整证据 | B | C 日志、D 证据、E 回查 |
| PromptManifest/CompactionCheckpoint | 前缀和配置版本、源边界、摘要身份、必须保留事项、Token/usage | B | C 恢复、D Skill/子上下文、E Inspector |
| Authorization/PatchPlan | 范围授权与精确票据可区分；前态、后态和部分应用可定位 | B | C 恢复与交互 |
| VerificationRecord | 真实检查种类、来源、退出/解析状态、代码版本、结果 | B | C Job 接入、D 学习、E 对照 |
| ProcessJob/ControlCommand/Checkpoint | 进程身份、受理/完成语义、已提交事件、待协调调用 | C | D 取消/学习、E 时间线 |
| EvidencePack/SkillVersion | 来源、适用/不适用、作用域、内容哈希、审核、运行固定版本 | D | E 泛化评测 |
| SubtaskSpec/Result | 目标范围、预算、只读权限、父任务版本、证据与不确定性 | D | E 成本/时间对照 |

本地存储不能持有写事务等待模型、命令或大文件 I/O。文件系统与 SQLite 不是同一事务资源，工件登记/写入/就绪及恢复归属必须明确。旧 JSON 只读导入保留原件；无需为未知格式编造自动迁移。

## 4. 分阶段完成线

| 阶段 | 结束时必须存在 | 结束时不能要求 |
|---|---|---|
| A | 可定位代码/配置基线、当前可运行路径与差距记录、可重复评测输入、真实环境限制 | 把已知旧行为修成目标新行为；性能改善 |
| B | 唯一持久身份与工件基础、原生工具、稳定前缀、Token/压缩、范围授权、类型化验证 | ProcessJob 完整中断协调、学习和并行调度 |
| C | 同一 CLI 内长命令/控制/安全退出、恢复协调、证据不误信、旧记录导入策略落地 | Web、SSE、daemon、关终端仍执行 |
| D | 可用的仓库经验候选与审核、版本/回读、记忆新鲜度、受父预算限制的只读并行 | 全局自动学习、并行写入、模型训练 |
| E | 用户可读诊断与交付、关键对照结果及限制、最终首版使用文档 | 全模块都显著更快更便宜，或新平台/新模型全支持 |

即使某功能缺乏净收益，也应报告结果并选择合理默认开关，而不是伪造增益。关闭阶段不能隐藏核心必需检查未完成；可选范围不做时标为延后。

## 6. 验证与付费调用

先做针对性复现/测试，再做必要类型、构建或烟测；低影响可逆文档修改不为凑覆盖率新增测试。原始基线出现已知失败可以作为 A 的发现，不需要 A 修复；基线无法复现与功能已修复必须区分。

真实 API 对照使用用户现有获准配置。没有可用凭据或费用授权时，写明 NOT_RUN/INCONCLUSIVE 与影响，不能把假模型结果当在线验收，不能在文档里留下密钥。阶段主控只接收报告，实际调用由执行子 Agent 完成。

E 的任务数按原方案建议、可用环境与费用选择，原约 30 题不是每阶段强制新增 30 题。固定任务族、起始版本和预算，比较原版、协议/工件/压缩、Skill 开关、单/多 Agent；不穷举全部组合。报告失败样本、模型随机性和未实测功能。

## 7. 跨阶段交接与完成定义

上阶段报告交付实际合同、状态版本、测试结果、已知限制与必要入口定位。下阶段只消费已关闭交付，不重新全仓审计。发现影响当前因果路径的缺陷时定向处理；若要改变已批准范围或冻结合同，先经用户决定。

任务主控不得因缺少细节亲自研究代码：向执行子 Agent 索取定向报告。总进度由任务分发 Agent 依据用户明确决定更新；开发指南、阶段文件存在不代表阶段已开始。

各阶段报告准备好后提交用户讨论关闭。用户同意关闭后提醒建立 Git 检查点，下一阶段仍需单独启动决定。
