阶段执行状态：未启动。启动批准：无。主控：待用户指定。前置：D 已由用户明确关闭。

## 用户得到什么

能在终端理解当前上下文、缓存、工具与经验使用情况，看到与当前版本一致的交付结果；得到可复查的升级效果和失败边界，而不是未经验证的百分比。

## 验收与完成线

新增 ADD-INSPECT；从 A—D 已有证据继承原 44 项矩阵的适用结果，明确其中四项按增订延后。只有相关实现改变、失败或未验证才补测原项，不把 E 变成重新做 A—D。

综合对照遵循同模型/预算/环境与任务族隔离，记录真实 token、usage、耗时、成功/失败、摘要成本、子任务成本和学习成本。实际价格或缓存字段未取得时明确估计/unknown。费用预算未获准、在线环境不可用时报告未完成条件，不把缺失测试写成成功。

解释能力的最低示例：为何本轮压缩、哪些前缀变了、哪些工具原文被外置、哪条验证已过期、为什么加载/拒用某 Skill、子任务消耗多少。用户无需再靠模型猜正式状态。

性能提高不是无条件验收要求：若短任务开启某项能力更慢或更贵，应说明适用条件并选合理默认。若基础正确性失败则修复或报告阻塞，不能用总体平均收益掩盖。

## 交付与关闭

交付实际首版使用说明、配置/平台限制、可复查效果报告、模块状态和阶段报告。原升级方案保持不动；新的实施结果另写文档，不能回填原方案使其看似过去已实现。

报告计划位置：`../reports/E-stage-report.md`，子报告可放 `../reports/E/`。用户明确关闭 E 后，本轮整体完成状态才能由任务分发 Agent 更新，并提醒建立 Git 检查点。本阶段不发布站点、不推送、不自动改简历。
