# D 阶段：经验与协作

阶段执行状态：未启动。启动批准：无。主控：待用户指定。前置：C 已由用户明确关闭。

## 用户得到什么

完成有价值任务后自动得到待审核经验候选，审核后在当前仓库的适用任务中按需使用。复杂调查可分成两个独立只读子任务，父级仍负责修改、验证与交付。记忆能解释来源并识别过期事实。

## 阅读与范围

读[增订](../01-addendum.md)、[开发指南](../02-development-guide.md)、[主控规则](../04-controller-rules.md)、C 报告及必要 B 合同记录。原方案定向读 06—08、09 的学习证据部分、13 的 Skill/多 Agent 对照。

D 不引入常驻学习服务、全局 Skill 自动迁移、全自动脚本发布、向量检索服务、并行写入或递归 Agent。不能把实施团队“主控派发可写子 Agent”的规则带进 SkillForge 产品。

## 验收与完成线

主要原 ID：KS01—KS10。新增 ADD-LEARN。Skill 候选必须体现问题签名、前提、诊断、条件化步骤、验证、不适用和证据；不能仅把旧 pytest 通用模板改个标题。

文档型候选不要求每个都完整重跑原任务，但来源、新鲜度、冲突和内容检查不能省略。独立任务族上的正负例用于识别误用，E 再进行综合效果对照；候选检查通过不等于普遍正确。

学习费用在项目授权范围内单列，主任务结果先输出，学习失败可独立显示。前台退出时不会继续收费工作；重启恢复既有待办不能重复发布。已撤回技能不能静默用于新任务，运行中安全撤回应影响后续相关动作。

产品子 Agent 只读工具范围必须由网关约束，最多两个并行、深度一层。父 Agent 在一轮调查期间暂停写入；外部变化依靠相关文件哈希识别。验证 Job 由父级申请。两个模型结果一致不是免复核证据，真实费用归入父任务。
