## 1. 重新对齐结论

本轮目标从 `SkillForge Lite v1` 调整为 `SkillForge Full Parity`：

> 在现有 `skillforge-harness/` 工程内，完成 pico 行为等价全覆盖，并叠加三方融合 v1 增量能力。

已确认的三个关键结论：

| 编号 | 主题 | 已确认结论 |
| --- | --- | --- |
| C-001 | pico 覆盖口径 | 采用“行为等价 + 测试”口径，不直接 fork pico，也不逐行照搬源码。 |
| C-002 | 增量层级 | 回到“三方融合 v1”：`repo_audit`、`code_change`、`test_fix`、TaskPacket、Evidence、Log MCP-like、Audit、SkillTree。 |
| C-003 | 工程策略 | 保留并重构现有 `skillforge-harness/`，不新开 v2 目录，不 fork pico。 |
| C-004 | CLI 形态 | 使用 pico 式主入口：`skillforge [prompt]` 与无 prompt REPL 是完整 agent 入口。 |
| C-005 | Skill 推广 | 自动生成 `SkillCandidate`，默认 quarantine，手动 promote 后进入 active。 |

## 2. 旧 Lite v1 边界处理

`SkillForge_Lite_v1_文档包` 中的缩减边界不再作为实现上限。Lite v1 中已完成的代码可以复用，但不得继续限制目标范围。

明确作废的 Lite v1 限制包括：

- `skillforge skills ...` 后置不进入 v1。
- 只做固定 pytest demo，不做完整 coding agent runtime。
- 不实现多 workflow。
- 不实现 Audit Subagent。
- 不实现完整 TaskPacket / Evidence Store / SkillTree 闭环。

新的边界以本目录、技术对齐文档和开发计划为准。

## 3. 新成功标准

项目完成时必须同时满足：

1. `pico` 的公开用户行为和核心模块能力在 `SkillForge` 中有行为等价实现。
2. 每个 pico 覆盖项在覆盖矩阵中有实现位置、验证方式和状态。
3. 三方融合 v1 增量能力在增量矩阵中有实现位置、验证方式和状态。
4. CI 默认使用 deterministic/fake provider，真实 LLM smoke 只作为可选验收。
5. 所有 run artifacts、sessions、skills 均使用 `.skillforge/...` 路径。
6. 没有证据不得声明完成；失败测试不得伪装通过。
