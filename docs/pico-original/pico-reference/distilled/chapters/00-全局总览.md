## 2. 核心内容摘要
* **系统三层架构划分**：
  * **控制面**：决定系统怎么跑。核心模块包括 `cli.py` (启动装配)、`runtime.py` (主循环与工具边界)、`context_manager.py` (Prompt组装)、`tools.py` (工具定义) 和 `models.py` (模型适配层)。
  * **状态面**：决定系统记住与恢复什么。核心模块包括 `memory.py` (分层记忆)、`run_store.py` (工件存储) 和 `task_state.py` (运行状态快照)。在磁盘上对应 `.pico/` 文件夹。
  * **证据面**：决定系统怎么被验证、比较和复盘。核心模块包括 `evaluator.py` (评测内核) 和 `metrics.py` (指标聚合)。在磁盘上生成 `trace.jsonl` 和 `report.json`。
* **单条请求流转生命周期**：
  1. CLI 解析命令行参数。
  2. `build_agent()` 装配出 `WorkspaceContext`、`SessionStore` 和具体的 `ModelClient`。
  3. one-shot 或 REPL 模式将用户消息交给主循环心脏 `Pico.ask()`。
  4. runtime 启动主循环，每一轮重新运行 `_build_prompt_and_metadata()` 拼装 Prompt。
  5. 调模型返回 raw output。
  6. 运行 `parse()` 过滤输出，判断其为工具调用、最终答案还是重试。
  7. 若为工具调用，走受控边界 `run_tool()` 校验并执行。
  8. 更新 session history、记忆与追加写 trace，产生 checkpoint。
  9. 直到模型给出 `<final>` 标签或超限，写出聚合 `report.json` 结束任务。
* **物理持久化目录结构 (`.pico/`)**：
  * `sessions/`：保存会话级状态（用于继续工作）。
  * `runs/`：保存单次运行工件（包括 `task_state.json` 状态快照、`trace.jsonl` 流日志、`report.json` 报告，用于回放和审计）。
  * `memory/`：保存长期沉淀事实的 Durable Memory（项目约定、用户偏好等）。
