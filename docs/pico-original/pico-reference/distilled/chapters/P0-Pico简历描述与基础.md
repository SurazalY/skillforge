## 2. 核心内容摘要
* **简历描述要点（v2.0 与 v1.0 演进）**：
  * **v1.0 初始版**：统一模型接入、工具执行、会话状态和工件落盘，支持 2 类模型后端、7 类工具、3 类工件；设计分层上下文治理预算；结构化管理任务/文件摘要和会话笔记，并结合新鲜度校验。
  * **v2.0 优化版**：主要优化了记忆模块与任务恢复机制，增加了 Checkpoint/Resume 机制，能够识别 Workspace 漂移并覆盖 10 个恢复场景。
* **学习方法论（怎么学）**：
  带着问题去读模块文档和代码，看完一章输出“模块解决什么问题、怎么做、为什么这样做”；反复口头讲述项目主链路直至讲顺（即用户请求 -> CLI装配 -> ask()主循环 -> 组装prompt -> 模型返回 -> parse()解析 -> 工具执行 -> 状态更新与trace落盘）；鼓励手动修改策略、规则或添加工具进行实战改造。
* **安装与 Provider 配置**：
  * **基础安装**：使用 Python 3.10+。利用 `uv sync` 同步依赖，或通过 `pip install -e .` 以可编辑模式安装。支持 `pico` 命令行直接启动。
  * **推荐后端配置**：默认推荐 `openai` provider 搭配 `Right Code` 中转。需要配置环境变量 `OPENAI_API_KEY` 及 `OPENAI_API_BASE` (如 `https://www.right.codes/codex/v1`)，默认模型为 `gpt-5.4`。
  * **其他后端**：支持 Ollama 本地模型 (如 `qwen3.5:4b`) 及 Anthropic 兼容接口 (配置 `ANTHROPIC_API_BASE`、`ANTHROPIC_API_KEY` 与 `claued-sonnet-4-6`)。
  * **缓存机制 (Prompt Cache) 提示**：只有 `openai` 兼容链路支持缓存发送，若 `base_url` 命中 `openai.com` 或 `right.codes` 才会自动携带缓存字段（保留策略为 `in_memory`），而 `anthropic` 与 `ollama` 链路在当前源 MD 版本中未接入 prompt cache 复用。
