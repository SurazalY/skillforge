# 90-针对项目描述的逐字面试话

## 1. 基础定位
* **原章节标题**：`【重要】90-针对项目描述的逐字面试话`
* **源 Markdown 位置**：行 3651 - 4585
* **核心思想与场景**：
  将 Pico 从“Demo 玩具”升华为一套生产级受控的 **Agent Harness 架构系统**。针对技术面试中的深度问答场景，提供较详实、带数据、带 Trade-off 辩护的逐字话术，应对面试官对工程细节的“拷问”。

---

## 2. 核心问答与逐字话术要点（骨架与干货数据）
* **Q1：什么叫 Agent Harness？为什么不是普通 Agent 聊天？**
  * *话术要点*：Agent 决定动作，Harness 提供软件脚手架来约束动作、管理上下文、记录状态、提供安全围栏与自动化评测闭环。Harness 决定了模型能走多远、走多稳。
* **Q2：能讲讲 Pico 的五层运行链路吗？**
  * *话术要点*：
    1. *启动装配层*：命令行解析为 `WorkspaceContext`、`SessionStore` 等运行时对象图。
    2. *上下文构建层*：按 Section 预算和优先级动态组装 Prompt 前缀。
    3. *控制循环层*：Runtime 执行 While 循环闭环推进（感知-决策-行动-记录）。
    4. *执行与状态更新层*：网关式工具执行（校验、审批、路径防逃逸），更新 memory 状态。
    5. *持久化与审计层*：Session 数据服务于下次恢复，Run Artifacts (Trace/Report) 独立沉淀用于事后分析。
* **Q3：工具是如何保证安全，防止逃逸的？**
  * *话术要点*：
    * *路径防逃逸*：使用 `commonpath` 算法核验解析后的绝对路径，越过 `../` 或 symlink 的逃逸直接拒绝。
    * *高风险审批*：对于 write/shell 工具，走 Approval Policy 钩子，支持只读模式与拦截重复调用。
    * *精准 Patch*：`patch_file` 的 `old_text` 若匹配不到或匹配多次直接报错，防止破坏代码库。
* **Q4：长上下文治理是如何做裁剪和预算管理的？**
  * *话术要点*：使用 Section 联合装箱与削减算法。超过 12000 字符时，按 `relevant_memory -> history -> memory -> prefix` 优先级自上而下裁剪，各 section 预设 25% 初始预算的 Floor 保底，`current_request` 绝对不裁。
  * *干货数据*：在 12 组变量组合配置下，平均 prompt 长度从 `7082` 压到 `5664`（平均压缩率 `16.19%`，最高 `33.28%`），100% 保证当前请求不被裁坏。
* **Q5：记忆系统是如何防过期，并且降低重复读文件次数的？**
  * *话术要点*：分层工作记忆绑定 `file_freshness` 文件哈希。在 Prompt 拼装时重新计算哈希，若发现指纹不符，旧文件摘要主动失效；在执行写工具后物理注销缓存。
  * *干货数据*：在记忆依赖任务中，follow-up 阶段重复读文件次数从 `60` 次降为 `0` 次，平均工具步数从 `1.0` 降为 `0`，尝试次数从 `2.0` 降为 `1.0`。
* **Q6：你是如何做任务恢复与防旧状态误信（Workspace 漂移）的？**
  * *话术要点*：Checkpoint 包含任务目标、卡点、关键文件哈希和运行环境参数。恢复时计算物理文件和环境哈希，不一致判定为 Workspace 漂移并报警。
  * *干货数据*：覆盖 5 类边界共 10 个漂移场景，Workspace 漂移识别率 `100%`，`0%` 误信旧状态继续执行。
* **Q7：你是怎么做评测与消融实验的？**
  * *话术要点*：将评测拆为 Harness 稳定性、机制消融和 Provider 差异等多层。使用只读 fixture repo 物理拷贝隔离测试区。判定通过使用“步数在预算内、自动化 verifier 退出码为0、期望文件已修改、停机原因正常”的硬性四条件交集。

## 3. 面试官追问防守与表达风格
* **防守策略**：
  * **先抑后扬（Trade-off 辩护）**：不要把方案说得相对完整无缺。面对追问时，主动说明“我们没有使用 Embedding 检索，因为在小范围内，基于规则和哈希新鲜度校验的精细控制，具有极佳的可解释性与调试效率”。
  * **拿数据说话**：避开模型生成的随机高分，强调“这是在多组对比配置下的平均稳定收益”。
* **模仿表达风格**：
  * 使用系统和后端架构成熟词汇（如“降级策略”、“缓存失效”、“信息契约”、“职责解耦”）。
  * 采用自信的架构师口吻，条理清晰地使用“首先、其次、再者、最后”进行叙述。
