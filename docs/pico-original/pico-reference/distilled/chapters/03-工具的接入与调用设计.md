# 03-工具的接入与调用设计

## 1. 基础定位
* **原章节标题**：`3-工具的接入与调用设计`
* **源 Markdown 位置**：行 1563 - 1928
* **本章在整份文档中的作用**：
  定义 Pico 工具执行的“安全边界与防逃逸护栏”，设计一套将危险的外部副作用动作锁在可控边界内的受控执行网关。这是区分“开发 Demo”和“生产级 Harness”的关键安全基石。

---

## 2. 核心内容摘要
* **安全网关前置拦截流 (`run_tool`)**：
  模型不直接与外部物理环境交互，工具执行需统一经过以下严格的前置校验与防线：
  1. **注册与声明**：必须是 `pico/tools.py` 预先静态注册的工具，禁止模型发明虚构动作。
  2. **参数安检 (`validate_tool`)**：强类型校验，限制值范围（如 timeout 在 1-120 秒）。
  3. **重复调用拦截**：若最近两次的工具名和参数与当前完全相同，直接打回 `repeated identical tool call`，阻止模型陷入消耗 token 的死循环。
  4. **越界边界校验 (`path()`)**：任何文件读写、扫描，均使用绝对路径计算，并通过 `commonpath` 算法核验是否超出当前工作区范围。凡是包含 `../` 或越过符号链接（symlink）逃逸的路径，一律拦截并报错。
  5. **审批策略校验 (`risky`)**：高风险工具（如修改文件、执行 shell）必须经过审批钩子（approval policy），未获授权直接打回。
* **工具箱角色与分工**：
  * `list_files` (列目录) / `read_file` (读文件) / `search` (字符串扫描)：低风险。
  * `write_file` (写文件) / `patch_file` (精确替换文件内容)：高风险。其中 `patch_file` 采用严格的单次精准匹配机制——若替换的目标文本 `old_text` 在文件里出现的次数不等于 1，直接报错，以防定位失效污染代码。
  * `run_shell` (命令执行)：极高风险。限制工作目录为根目录，采用白名单加载环境变量（不继承父进程全部 API Token 等敏感变量），做输出裁剪。
  * `delegate` (子 Agent 调查)：委派子任务。强制以 `read_only=True`、`approval_policy="never"` 的安全沙箱参数启动子 Agent，使其仅具备只读调查权限，无法写改代码。
* **副作用审计**：
  工具执行前后，对工作区做快照（Workspace Snapshot），输出会附带 `affected_paths` (被影响路径)、`workspace_changed` (工作区是否变更) 与状态，记入 Trace 和 Report。

## 5. 对标与复用指引
* **值得对标的结构**：
  * **“安全网关前置拦截”模式**：先校验、后审批、再执行、最终审计，这一逻辑在编写任何系统级、高风险交互模块的文档时都属于行业标准写法。
* **值得复用的写法**：
  * “这一层的设计思想是模型不能直接碰外部世界，所有动作都必须经过统一边界。”（定性安全重要性）
  * “`patch_file` 匹配不到或匹配多次直接报错，防止定位失效导致代码库大面积崩溃。”
* **不应机械照搬的地方**：
  * 纯同步阻塞式的人工审批（CLI input 确认）在非交互式后台运行（如 CI/CD pipeline）时会导致卡死。对非交互场景，应当对审批策略做异步扩展（如 Webhook 钩子或自动化白名单规则）。
