## 转换质量评估与限制记录

在精读源 Markdown 文件后，整理出以下转换缺陷与识别限制，后续 Agent 在阅读或对标时需特别注意：

1. **图片及图表完全缺失 (核心限制)**
   * **现象**：Markdown 中所有架构图、时序图、流程图均被转换为类似下面的文本占位符：
     `==> picture [55 x 9] intentionally omitted <== 图片加载失败 ----- End of picture text -----`
   * **影响**：无法从 Markdown 中直观获取 Pico 的全局总览图、运行时主循环图、上下文管理图、工具边界图、状态恢复图等视觉设计。
   * **对标建议**：**凡是涉及架构、流程、时序和界面截图的部分，必须回看原始 PDF (`2-pico.pdf`) 进行确认**。

2. **OCR 错字与识别粘连**
   * **现象**：部分章节标题或序号存在多余符号或标点错乱，例如：
     * 行181的标题识别为 `## 。 5. 过程中有问题就来群里问我...`
     * 行66的 `分层；在` 识别为单独行；行72的 `分` 被单独折行。
     * 行113的链接粘连：`1-代码仓库上下文设计.md📎02-运行时主循环...`
     * 行204的文字乱码：`Right Code` 附近有奇怪的空格和拼写错误。
   * **对标建议**：涉及代码类字段或技术术语（如 `PromptPrefix`、`WorkspaceContext` 等）时，应以代码逻辑为准。若有语句明显不通顺，需回看原 PDF 校验。

3. **非正常断行与段落破碎**
   * **现象**：由于 PDF 转 Markdown 时对排版栏宽的误判，部分长句子在段落中间被强制换行，导致语句被切碎。
   * **对标建议**：在进行横向分析或提炼写作风格时，注意忽略这些因转换导致的“断句”现象，原文档在 PDF 中其实是连贯的长句。

4. **表格与代码块识别不全**
   * **现象**：部分表格存在表头与内容折行重叠的问题。部分行号被硬编码进了代码段（如 `1 ad def build_agent(args): 2 ...`）。
   * **对标建议**：复制代码块时注意剔除混入的行号，并结合真实代码库核实。不确定处应清晰打标“需要回看源 MD 或原 PDF 确认”。
