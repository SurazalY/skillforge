# Pico 项目 Agent 参考指南 (AGENT_GUIDE)

本参考指南旨在为后续 Agent 快速理解本仓库核心资产、并用于“对标原文档结构与风格”编写新项目介绍时提供快速引导入口。

---

## 1. 基础认知与作用定位
* **资料来源**：本资料包基于工作区中的 `2-pico_perfect.md`（源自原始 PDF 文档 `2-pico.pdf` 经过 OCR 转换得到的约 27 万字符/270KB 级源 Markdown）。原文档是一套面向面试准备的本地代码智能体运行框架 (Agent Harness / Coding Harness) 系统设计与面试问答整理。
* **后续项目作用**：当后续 Agent 被指派去编写新项目的介绍文档、系统设计说明书或面试准备材料时，本资料包能够提供一套与原文档目录结构、叙述文风及论证逻辑相承接的框架指南。

---

## 2. 核心对标原则
1. **优先尊重原始目录与内容顺序**：后续新文档的骨架和逻辑顺序应尊重本资料包 `distilled/chapters/` 中确立的原始目录。应分清“整理后的文件编号”与“原文真实标题”（详见 [source-toc.md](source-toc.md)），不可将人工分配的编号与原文大纲混淆。
2. **控制上下文占用**：**后续 Agent 在每次任务中应避免读取完整的 `source.md` 副本**，这会造成不必要的上下文浪费。请优先阅读 [source-toc.md](source-toc.md) 确定物理定位，并定向阅读 `chapters/` 下提取出的轻量化摘要。
3. **事实与数据保守性**：新文档中对各模块的叙述应侧重于“防逃逸、防失控”的安全校验与 fail-closed 契约。文档中所引用的任何对比实验数据，必须明确区分原作者实验数据与后续项目实测数据，不确定处应清晰标注。

## 4. 后续 Agent 指导规范与参考标准

### 4.1. 写作与论证风格标准
* 编写新设计说明时，应参考原文的**“提出 AI 运行风险 -> 制定物理安全约束 -> 阐明系统 trade-offs -> 拿消融实验数据论证”**的论证逻辑。
* 段落多由 1-2 句的短句组成，并使用无序列表或网格表格进行结构化排布。
* 涉及关键代码时应指向具体的物理文件名和类名（如 `pico/runtime.py` 中的 `Pico` 类）。
* 写作要保持客观，不应使用带有主观吹捧或缺乏查证基础的词语。

### 4.2. 视觉排版与 PDF 回看标准
* **视觉局限性说明**：源 Markdown 丢失了全部图片和架构时序图。目前的排版与视觉分析仅是**基于 Markdown 残留物理信息的有限推测**，详见 [visual-style.md](analysis/visual-style.md)。
* **回看原 PDF 的触发条件**：
  * 需要画全局三层架构关系图时 -> 查看原 PDF `00-全局总览` 页。
  * 涉及主循环 ask() 时序推进时 -> 查看原 PDF `2-运行时主循环与执行编排设计` 页。
  * 涉及安全校验网关与 Approval 拦截逻辑时 -> 查看原 PDF `3-工具的接入与调用设计` 页。
  * 需要参考终端运行高亮截图与交互格式时 -> 查看原 PDF 简历与安装后的插图页。

## 5. 推荐的后续开发 Agent 工作流

1. **第一步：加载本导航文件**：确认对标原则与章节物理位置。
2. **第二步：按需载入章节摘要**：根据任务定位，使用 `read_file` 加载特定摘要。例如，修改安全控制时，载入 [03-工具的接入与调用设计.md](chapters/03-工具的接入与调用设计.md) 与 [90-针对项目描述的逐字面试话.md](chapters/90-针对项目描述的逐字面试话.md)。
3. **第三步：起草与核对**：根据 [writing-style.md](analysis/writing-style.md) 中的风格指南与 [reuse-guidelines.md](analysis/reuse-guidelines.md) 中的复用指南起草新文档，并核对专业术语（如“新鲜度、floor保底”）。确保在起草新文档时，不确定处应清晰注明“需要回看确认”。
